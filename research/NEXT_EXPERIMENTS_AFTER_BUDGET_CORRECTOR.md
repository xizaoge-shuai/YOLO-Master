# 从预算校正 pilot 到正式论文实验

状态：2026-09-25 的实验决策与执行规格；以下新训练均尚未启动。
已完成证据：budget-corrector-job-start-7U9Q7DSc，18 次完整训练，400/100，3 个种子。

## 本轮结论与停止规则

- 校正器相对同预算 Transport 的 best AP：10% 为 -0.2270，25% 为 -0.1116。
  final AP：10% 为 -0.1067，25% 为 +0.0391。不能只报告优于 Mix 的部分。
- 训练查询上的重建误差明显下降，但尚未转化为稳定检测收益。
  背景占优、任务目标不匹配和特征分布随训练变化均是待检验假说。
- transport-p25-s1 的训练和验证同时出现耗时异常。保留原结果，
  用独占 GPU、资源监控、交错顺序重测配对方法。不得只删除不利时间点或种子。
- 不再用当前 400/100 子集做宽泛参数网格搜索。最多一轮针对性改进；
  完整数据加载、评估与 baseline 准备现在开始，不以方法先“跑赢”为前提。
- 小规模负结果不能直接推出全量无效。第一批全量保留当前校正器作为诊断对照。

## 两条工作同时推进

### A. 全量 VisDrone 基线与评估

工程前置：
1. 固定 6,471 train / 548 val / 1,610 test-dev；不继续使用训练集内部 400/100。
   超参数与训练轮数只用 train/val；test-dev 留给配置冻结后的最终评估。
2. 原数据不改写。在派生标注中明确记录并过滤已发现的一个零高度训练框。
   保留压缩包中的原始 ignored-region 标注，接入 VisDrone 官方评估工具。
   如额外使用 COCO-style APs，清楚说明面积、maxDet 和 ignore 处理，勿混称官方分数。
3. 将 GPU 常驻全部特征改为按批从 CPU/磁盘读取。全量 C2 原始特征约 44.43 GiB，
   val C1 约 1.88 GiB，尚未计模型、临时张量和序列化。
4. 显式分离 train/val cache manifests，按样本 ID 校验无交叉、标签与几何一致；
   用同一批真实图像/预测核对缓存路径、在线路径、官方评估和自定义评估的差异。
5. 固定分辨率、检测头、损失和每个方法的选择规则。先跑 1 epoch 测试吞吐、
   存储 I/O 和估计总 GPU 时间，然后才排长任务；记录进程/利用率/功耗等资源日志。

第一批全量（seed 0，作为管线与方法诊断，不作为正式三种子最终表）：
- C1 原图缓存；
- C2 原图＋真实水平翻转缓存；
- C2-Mix 25%；
- C2-Transport 25%；
- 当前 reconstruction-only C2-Correct 25%；
- Full-online frozen DINO + 相同连续几何增强；
- YOLO-Master-N scratch 实用对照，明确它与冻结 DINO 的训练配方差异。

YOLO-Master 论文配方对照与 D1 等成本对照是两种实验：
- 论文参考：600 epochs、640、batch 256、SGD 等，先锁定论文对应代码/config。
  若使用小物理 batch + 梯度累积，注明 BatchNorm 等差异，不写“精确复现”。
- D1 成本对照：同硬件、同数据/评估、同总 GPU 时间，报告冻结/可训练/全部参数。
  不能用同 epoch 数、或“只算检测头训练时间”，代替等成本比较。

在完整验证集确认实现和训练稳定后，补 seed 1/2；同时保留现有负结果。
新训练是后续实现任务，本分析不把当前 pilot 脚本冒充全量训练器。

### B. 一轮有限的任务相关校正诊断

先用现有 checkpoint 做诊断，不立即增加网络容量：
- 同一组未参与校正器训练的图像与增强视角，比较 exact / Transport / Correct。
  可以使用开发验证集做模型选择诊断，但不更新校正器、不称其为最终测试。
  额外 DINO 提取计入诊断成本；不能隐含免费校准。
- 报告前景/背景、小目标/大目标、各层及缩放幅度的特征误差。
- 同一个冻结参考检测头分别读取三类特征，测真实框的分类/定位损失或 AP；
  再检查当前联合训练头，区分表示误差与检测头适应差异。
- 扫描残差幅度作为只读特征诊断时，不宣称等价于训练全程采用该门控。
  未实施增强校正的常规原图验证仍沿用原始流程。

最多两个预先指定的训练变化，先固定 25% 查询预算、原样本顺序、3 个种子：
1. 前景/背景分开归一的重建目标，避免仅靠像素数量决定损失权重；
2. 在 1 的基础上加入检测任务约束。用已有查询的真实增强框或同一头的停止梯度
   exact-feature 输出作监督；后一种只能称预测一致性，不能当数据集真值。

诊断先决定分支：若未见图像上的误差没有改善，优先处理校正器泛化，暂缓直接堆任务损失；若误差改善而固定检测头的检测损失/AP 不改善，再优先上述任务相关监督。训练查询上的误差下降不能独自区分这两种原因。

使用查询一次得到的 exact features；不增加 backbone 查询，不接触 test-dev。
额外检测头前向/反向、门控和优化时间都计入总成本。
与 Transport 和当前重建型 Correct 都比较，不只比较较弱的 Mix。

推进标准：在完整验证集/小目标指标上有实际收益且总体时间仍划算；
报告完整种子分布和 best/final，先不设事后有利的显著性阈值。
如果两种定向变化仍无增益，暂停“学习残差恢复优于传输”的主张；
重新检查问题机制或研究方向，不能靠扩大表格来弥补方法贡献不足。

## 什么时候跨数据集

- 现在：完成 COCO 下载/磁盘规划与标注/evaluator 准备；可先做小规模
  source-to-target 诊断，及早暴露原先的域外问题。
- 全量：COCO train2017 118,287 图和 instance JSON 就绪、流式缓存与评估通过后，
  把 VisDrone 选定配方迁移到 COCO train2017 / val2017（5,000）。
  参数选定后冻结，不在看到 COCO 测试结果后反复改配方却称“未调参迁移”。
- 当前仓库 COCO 只有验证图和 val JSON，不能视为训练集已安装。
  当前 S/16 三层 FP16 的 COCO C1 约 406.11 GiB，超出此前核查的可用磁盘；
  C2 更大。若采用压缩/量化，要作为所有比较臂共同的新设置，并做精度消融。

区分三种完全不同的结论：
1. 多数据集适用性：每个数据集独立训练校正器与检测头。
2. 校正器零目标域校准迁移：只在源域训练校正器，到目标域冻结；
   目标检测头仍在目标训练集训练。这不是零样本目标检测。
   若目标在线 queries 仍供检测头使用，也必须计数，不能称零目标域 backbone 调用。
3. 带目标域适配：源域初始化＋固定预算的目标域校正器更新；
   与目标域从零训练、Transport、Mix 比较，源域训练成本单列或明确摊销。

若要声称跨域，至少记录 VisDrone→COCO 与 COCO→VisDrone 的对称设置；
不要把“两个数据集各自重训都有效”写成“一个校正器跨域泛化”。

## 什么时候跨模型

- 第一批全量 VisDrone 的管线和候选方法确认后，先加 DINOv3 ViT-B/16。
  S/16 与 B/16 支撑同族规模适用性，不自动等于跨架构泛化。
- 如果论文声称更普遍的视觉基础模型适用性，再加另一预训练模型族
  （例如 DINOv2）或另一架构；重新核对 patch 网格、层选择、维度和预处理。
- 每个 backbone 内各方法共用同样的特征接口和检测头。更换骨干重新训练
  校正器支撑“算法可用”，并不支撑“同一组校正器权重可直接迁移”。
- 从 S/16 的 384 维到 B/16 的 768 维不能直接加载当前共享卷积权重；
  若设计可迁移适配器，其参数和校准成本必须另外报告。

建议节约预算的实验矩阵，而非从第一天全笛卡尔积：
- VisDrone × DINOv3-S：完整机制、预算和基线实验；
- COCO × DINOv3-S：主要方法/强基线，检验数据集适用性；
- VisDrone × DINOv3-B：主要方法/强基线，检验模型规模；
- COCO × DINOv3-B：若前三项稳定，补齐 2×2 主表；
- 另一模型族：至少一个全量数据集的关键比较，若标题声称跨基础模型则不能省略。

## 论文最终应呈现的实验

| 优先级 | 实验 | 解决的问题 | 主要输出 |
|---|---|---|---|
| 必须 | 官方完整划分的主结果 | 实际检测是否有效 | AP、AP50、AP75、明确口径的 APs/APm/APl，3 seeds |
| 必须 | 总成本-精度曲线 | 是否值得节省训练计算 | 0/10/25/50/100% 查询，构建+训练+验证，等时间比较 |
| 必须 | 强缓存与在线基线 | 是否只是更多缓存/更多在线监督起作用 | C1/C2、少量真实缩放视角、Mix、Transport、full-online |
| 必须 | 机制与消融 | 为什么重建误差下降不等于 AP 上升 | 无条件/条件、重建/任务约束、前景/背景、残差门控 |
| 必须 | 小目标与增强分析 | 是否解决最初提出的问题 | 小目标 AP/召回、缩放/平移/裁剪/翻转分组，失败例 |
| 必须 | 存储及摊销 | 缓存代价是否被藏起来 | GiB、CPU/GPU 内存、I/O、首次训练/多次复用与 break-even |
| 依主张必须 | 跨数据集/校正器迁移 | 通用适用性与域外能力 | 独立重训、源域冻结迁移、目标域适配分开 |
| 依主张必须 | 跨模型/检测头 | 是否仅对当前 DINO-S/custom head 成立 | 第二骨干，必要时第二检测头/模型族 |
| 补充 | 更广泛基线与敏感性 | 排除常见替代解释 | FroFA/LOFF-TA 检测适配、LoRA 等实用对照、rank/参数量/seed |

主文优先一张总成本-AP曲线、一个全量主表、一个强基线/消融表、
一张“重建与检测错位”的机制图、一张迁移图。细节放补充材料。
多视角真实缩放缓存对照必须补，但不需要先做几十种缓存大小才能推进全量。

FroFA/LOFF-TA 是分类领域工作的检测适配，标明适配方式并沿用检测真值；
不能将其原论文分类精度拿来与本项目 AP 数字比较。
