# 吞吐修复计划

本轮完成诊断，没有实施训练代码补丁或重启作业。

1. 优先在可用的独占GPU时间段或另一健康GPU上执行后续任务，记录硬件与并发；当前GPU1异常，不将任务迁过去。其他用户任务保持原状。
2. 新执行版本增加分阶段CPU/传输/GPU计时，区分缓存读取、解量化、传输、检测头前后向与优化器；嵌套计时不重复收费。
3. 在相同样本计划下增加有界CPU预取与固定内存buffer，降低逐样本拷贝并尝试传输/计算重叠；INT8先验证传输较小编码后在GPU解量化是否保持数值与代价可接受。GPU解量化是候选，尚未实施或确认加速。
4. 使用原有计划逐batch核对样本、增强参数、特征与标签；验证随机状态、优化器、调度器和checkpoint恢复，防止提速时改变实验含义。新版本另记source/hash和成本；不能默改冻结源码后混入旧运行。
5. 调整batch、减少epoch、开启AMP或改变确定性会改变数值/训练配方，需独立配置并让对应baseline同口径比较。它们不作为本轮已完成的“无损提速”。

仍待确定的是各阶段占比及可用独占资源，而非是否将100轮误设成更大轮次。当前不声称已经修复吞吐或取得速度增益。
